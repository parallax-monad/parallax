# P0-C Risk internals and Backend handoff

This is an additive Risk-side implementation of the [#70 Product semantic freeze](https://github.com/parallax-monad/parallax/issues/70) for [#71](https://github.com/parallax-monad/parallax/issues/71). It does not change Shared Contracts or the public API. The existing Monad × Kuru × Moss evaluator and the Orchestrator's one-third reduction fixture remain compatibility behavior. Backend must use the new solver, rather than the fixture, for the real P0 path.

## Quote Fidelity and diagnosis

`compareQuoteFidelity` accepts an immutable selected quote and a current quote only for the same chain, protocol, token pair, and exact input amount. Both records must include quote identity, provenance, block, and time. The current quote must be verified and no earlier than the selected quote. Missing or incompatible context returns `UNKNOWN` and emits no degradation Observation. The delta is an atomic integer; the relative delta is an exact numerator/denominator pair. A zero selected output has no relative ratio.

`evaluateP0Risk` adds a fail-closed gate around the existing generic evaluator. It keeps Quote Fidelity, Evidence State, caller constraints, and the base verdict separate. `QUOTE_OUTPUT_DEGRADED` is descriptive; it is not a caller tolerance. A missing baseline blocks a full P0-C `PROCEED`, although independent execution checks may still run. Provider failure, stale or incomplete evidence, and missing constraint evidence produce `UNKNOWN`. A verified caller constraint violation produces `STOP` unless an applicable child adjustment is verified.

Before emitting `ADJUST`, the exported gate re-applies the solver's verification boundary to the supplied candidate: a mock, replayed, indistinct, unbound, or unchanged child record leaves `STOP`. `VerifiedCandidate` preserves chain, protocol, token pair, runtime version/revision, selected quote ID, candidate input/output and quote ID, quote block, and observation time. The gate requires a positive candidate input, the same economic and runtime context as the selected quote, candidate block/time no earlier than the selected baseline, an exact verification-block match, and verification time no earlier than candidate observation. It also receives the trusted identity of the current Run as `parentRunId` and requires a non-empty expected parent, a non-empty proof parent, and `proof.parentRunId === parentRunId`, so a child Run verified for a different parent cannot support `ADJUST` while the child Run must still be non-empty and distinct from its parent. Missing or malformed nested verification fields, including a missing or malformed expected parent identity, fail closed without throwing. Legacy transaction minimum received is not copied into the new caller-constraint set.

`checkedScope` records which checks ran; it does not establish that they passed. For every currently failed caller declaration, the candidate's child verification must carry one `PASS` outcome for that exact `declarationId` and constraint name, bound to the same child Run and candidate quote. A same-name result for another declaration, a missing result, `FAIL`, or `UNKNOWN` cannot support `ADJUST`. When transaction protection is the base blocking condition, its separate child result must also be `PASS` and bound to that child and quote.

The constraint evaluator accepts only explicit caller declarations. Each declaration retains its ID and compares to a named verified metric in matching units; total cost also requires the same cost asset. The measured metric belongs to the constraint name rather than to a declaration, so several caller declarations of the same name may each be evaluated against the same unique measured record (a loose declaration and a strict declaration over one verified price impact produce `PASS` and `FAIL` respectively). When more than one evidence record claims the same name the metric is ambiguous, and every affected declaration fails closed to `UNKNOWN`; records are never resolved by arbitrary first- or last-match order, so duplicate same-name evidence can never produce `PASS` or `FAIL`. The caller must supply the price impact, effective rate, total cost, or gas evidence through a provider-neutral mapping. If a metric is unavailable, its constraint is `UNKNOWN`. No estimate is synthesized from a quote. Causes have separate required evidence kinds and an explicit causal-support attestation; quote degradation alone supports none of them.

## Solver and verification port

`solveSelectedTargetOutput` explores increasing exact-input amounts using an initial step that doubles after each unsuccessful observation. It caps each candidate at the configured maximum and stops after `maxEvaluations`. It uses the evaluator's actual quoted output and makes no monotonicity, minimum, or global optimum claim. The selected exact-input baseline must be a canonical atomic decimal and a positive swap input; a malformed or zero baseline fails closed to `UNKNOWN` without throwing and no evaluator call is made. Exhausting the domain or evaluation budget returns `NO_VALID_CANDIDATE`. Quote failure, evaluator failure, and unknown evidence return `UNKNOWN`. A quote that reaches the selected output without complete verification remains `PROPOSED`.

The evaluator is an asynchronous Backend port. Backend must bind each candidate to a fresh quote, exact prepared unsigned transaction, Provider evaluation, Risk evaluation, and verified child Run. It must supply the child identity, `parentRunId`, actual output, quote identity, state block/time, provenance, checked scope, child constraint outcomes, any applicable child transaction-protection outcome, and Action Gate attestation. Risk checks those fields before labeling a candidate `VERIFIED` and requires `verificationBlock` to equal the candidate quote block and the verification time to be no earlier than the candidate quote's `observedAt`; the solver copies candidate economic and quote context into the returned `VerifiedCandidate` so the gate can revalidate the binding. This local record is not itself a public Action or proof that Backend has run the sequence. Before surfacing `ADJUST`, Backend must persist and validate the child Run under the existing Action Gate and recheck if relevant state changes before signing.

The current generic Evidence and public Contract do not expose every metric required for all four economic constraints or every Cause. Backend should report those inputs unavailable until it has verified provider-neutral evidence, and Contract Owner must review any later shared representation or public projection. No Provider-specific raw response or protocol calldata belongs in Risk.
